# ADR-0006: 使用 Pusher Channels 實現即時通訊

## 狀態
已接受

## 背景
需要實現即時功能，包括：
- 位置更新即時推送
- 成員到達通知
- 戳人事件通知
- 聊天訊息即時傳遞

## 決策
使用 Pusher Channels 作為即時通訊解決方案。

## 理由
- **易於整合**:
  - 提供 WebSocket 抽象，無需直接管理 WebSocket 連接
  - 簡單的 API，易於使用
  - 良好的文檔和 SDK 支援

- **可靠性**:
  - 託管服務，無需自行維護基礎設施
  - 自動重連機制
  - 高可用性和擴展性

- **功能豐富**:
  - 支援頻道訂閱和事件推送
  - 支援私有頻道和存在頻道
  - 提供客戶端事件（client events）

- **成本效益**:
  - 免費方案適合開發和小型應用
  - 付費方案價格合理

## 替代方案考慮
- **Socket.io**: 需要自行部署和維護伺服器
- **Firebase Realtime Database**: 綁定到 Firebase 生態系統
- **自建 WebSocket**: 開發和維護成本高

## 後果
- 依賴第三方服務，存在服務中斷風險（但 Pusher 有高可用性保證）
- 需要處理 Pusher 連接失敗的情況
- 對於極高並發場景，可能需要升級付費方案
- 但對於本專案需求，Pusher 是最佳選擇
