# ADR-0010: 使用 LRU Cache 進行後端快取

## 狀態
已接受

## 背景
需要優化 API 性能，減少資料庫查詢。主要快取需求：
- 活動列表
- 對話列表
- 用戶資訊

考慮到部署環境可能是 serverless（如 Vercel），無法使用 Redis 等外部快取服務。

## 決策
使用 LRU (Least Recently Used) Cache 進行記憶體快取。

## 實現細節
- 使用 `lru-cache` npm 套件
- 快取熱點資料（如活動列表、對話列表）
- 設置合理的 TTL (Time To Live)
- 實現快取失效機制

## 理由
- **Serverless 友好**:
  - 無需外部服務（如 Redis）
  - 適合 Vercel 等 serverless 平台
  - 降低基礎設施複雜度

- **簡單有效**:
  - 對於中小型應用，記憶體快取已足夠
  - 簡單的 API，易於使用
  - 自動處理快取淘汰

- **性能提升**:
  - 減少資料庫查詢
  - 提高 API 響應速度
  - 降低資料庫負載

## 限制
- **記憶體限制**:
  - Serverless 函數記憶體有限
  - 無法跨實例共享快取
  - 適合快取小量熱點資料

- **資料一致性**:
  - 需要手動處理快取失效
  - 可能出現短暫的資料不一致

## 替代方案考慮
- **Redis**: 功能強大但需要額外基礎設施
- **無快取**: 性能較差，資料庫負載高
- **CDN 快取**: 只適合靜態內容

## 後果
- 需要仔細設計快取策略
- 需要處理快取失效邏輯
- 對於高並發場景，可能需要升級到 Redis
- 但對於當前規模，LRU Cache 是最佳選擇
