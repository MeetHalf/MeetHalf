# ADR-0004: 使用 Prisma ORM 進行資料庫操作

## 狀態
已接受

## 背景
需要選擇一個 ORM 或查詢構建器來與 PostgreSQL 資料庫互動。主要需求包括：
- 型別安全的資料庫查詢
- 自動遷移管理
- 良好的開發體驗
- 與 TypeScript 完美整合

## 決策
使用 Prisma ORM 作為資料庫抽象層。

## 理由
- **型別安全**:
  - 自動生成的 TypeScript 型別
  - 編譯時檢查查詢錯誤
  - 減少運行時資料庫錯誤

- **遷移管理**:
  - 聲明式的 Schema 定義（Prisma Schema）
  - 自動生成遷移檔案
  - 版本控制的遷移歷史

- **開發體驗**:
  - 優秀的 Prisma Studio（資料庫 GUI）
  - 清晰的查詢 API
  - 良好的文檔和社區支援

- **性能**:
  - 查詢優化器
  - 連接池管理
  - 支援原始 SQL 查詢（當需要時）

## 後果
- 學習曲線：需要理解 Prisma Schema 語法
- 遷移過程需要謹慎處理，避免資料遺失
- 某些複雜查詢可能需要使用原始 SQL
- 與 Sequelize、TypeORM 等相比，Prisma 相對較新，但生態系統正在快速成長
